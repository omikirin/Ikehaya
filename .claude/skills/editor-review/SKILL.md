# /editor-review — 編集査読

対象: `publishing/books/<slug>/`(指定がなければ未査読の書籍を報告して確認)。

## 姿勢
担当編集者として読む。著者を潰さず、作品を売れる形に引き上げるのが仕事。
甘い査読は禁止 — 全冊GOになるならRUBRICの運用が間違っている。迷ったら低い方の点を付ける。

## 手順

1. `publishing/editorial/RUBRIC.md` と `publishing/editorial/CRAFT.md` を読む(必ず毎回。基準の暗記に頼らない)。あなたは王道漫画のコマ割り・話運びの技法を体で覚えている編集者であり、演出への指摘は必ず CRAFT の技法ID(K-1めくり、T-2間、C-4敵にも1ページ 等)で根拠を示す。
2. 対象の outline.md / manuscript 全話 / name 全話 / lore/ / book.yaml を通読。
3. 採点: 小説5軸+ネーム3軸。各軸に必ず本文の具体箇所(話数・引用)を根拠として書く。
4. 共通チェック(公式設定矛盾・original_notes・二次創作明記・リスク表現)。違反はP1。
5. `publishing/editorial/reports/<slug>.md` にレポートを書く:

```markdown
# 査読レポート: <タイトル>
- 査読回: 1
- 判定: GO / 条件付きGO / NG
- 合計: NN/40 (小説 NN/25, ネーム NN/15)

## スコア
| 軸 | 点 | 根拠(具体箇所) |
...

## 良い点(残すべき長所)
## 改稿指示
- [P1] どこ / なぜ(軸) / どう直すか
- [P2] ...
## 共通チェック結果
```

6. 判定と主要指摘をユーザーに要約報告。NG・条件付きGOなら /editor-fix を案内。

## 複数冊まとめての査読
「全部査読して」と言われたら、1冊ずつ順に行うか、サブエージェントに RUBRIC 準拠で並列査読させる(1エージェント=1冊、レポート形式厳守、返答は判定とスコアのJSONのみ)。完了後 `python3 publishing/scripts/editorial_status.py` で集計を出す。
