# /ninja-novel — ジャンル×キャラ選択で小説を一冊作る

CryptoNinja の二次創作小説を「選ぶ→自動で一冊」まで運ぶ。工程は既存パイプラインを使うが、
**本文はフィクション用ルール(後述)で book-write の文体規則を上書きする**。

## フェーズ0: 選択

1. `mcp__NINJAMCP__list_characters` で一覧を取得。
2. AskUserQuestion で1回だけまとめて聞く:
   - **ジャンル**(例: バトル/ミステリー/ほのぼの日常/恋愛/ダークファンタジー。自由入力可)
   - **主役キャラ**(クラン別に代表を提示。「おまかせ」ならジャンル適性で選定)
   - **長さ**: 短編(8千〜1.5万字/4〜6話) / 中編(3〜5万字/8〜12話)
3. 選択済みの指定がプロンプトに含まれていれば質問はスキップ。

## フェーズ1: ロア収集(企画の前に必ずやる)

- `get_character` で主役+絡めたい関係キャラの完全設定を取得
- `get_worldview`(seasons/clans/relations_map/unconfirmed_notes)で舞台を固定
- 物語の鍵になる要素(忍術・武器・因縁)は `search_lore` で裏取り
- 結果を `publishing/books/<slug>/lore/` に Markdown で保存(執筆時の参照資料)

**設定の優先順位**: 公式設定 > unconfirmed_notes(創作の余白として自由に使える) > 完全オリジナル。
公式設定と矛盾する改変はしない。余白を使った独自解釈は `lore/original_notes.md` に明記。

## フェーズ2: 企画 (/book-plan を小説仕様で)

`publishing/books/_template` をコピーし、outline.md を**プロット**として書く:
- ログライン1行(誰が・何を賭けて・何と戦う)
- 三幕構成: 発端(日常と事件)→中盤(試練と転落)→結末(クライマックスと変化)
- 話数割り(1話=2,000〜4,000字)。各話に「引き」を1行ずつ設計
- 主役の内的変化(最初と最後で何が変わるか)

book.yaml: title はジャンル読者に刺さる形(キャラ名+フック)。description は
あらすじ+「CryptoNinja二次創作」の明記。keywords に「CryptoNinja」「クリプトニンジャ」を含める。

## フェーズ3: 執筆 (/book-write のフィクション上書き)

- 文体: 地の文は**だ・である調**、三人称一元視点(主役固定)を既定とする
- 各話の型: 前話の引きの回収→山場→次話への引き
- キャラの口調・一人称・関係性は `lore/` の設定に厳密に従う。忍術の効果を勝手に盛らない
- 戦闘・術の描写は五感+代償(疲労・リスク)を必ず入れる
- 1話書くごとに保存し、話数・文字数・引きの一行を報告

## フェーズ4: 校正〜EPUB (/book-edit → /book-build)

- /book-edit の3パスに加えて**設定整合チェック**: lore/ と本文の矛盾(口調・術・関係性)を洗う
- 表紙: `get_character_image`(official=CC0)を取得して `cover/` に保存し、タイトル文字入れの
  デザイン指示を `cover/cover_brief.md` に書く
- /book-build で EPUB生成→機械検収エラー0まで

## フェーズ5: 発売・販促 (/book-launch + 軍配)

- /book-launch で KDP入稿素材・X告知(#CryptoNinja タグ)・LP骨子を生成
- 販促計画の品質検収は pro-marketing-director(軍配)を起動して行う
- ファンアート文脈での拡散(キャラ公式コミュニティへの共有)を告知案に含める

## 注意
- 販売前に CryptoNinja の最新の二次創作・商用利用ガイドラインを確認するようユーザーに必ず伝える
  (作品はCC0運用で知られるが、最新の公式案内が優先)。
- キャラを著しく貶める展開・公式イメージを毀損する内容は書かない。
- 一気に全話やらず、フェーズ2(プロット)完了時に一度ユーザー承認を取ってから執筆に入る。
